## THE CONDUCTOR'S READINGS, SAID OUT LOUD

The plan handed down eight readings. Each is repeated here in this lamp's own
words, with what it cost, because a ruling repeated is a ruling that can be
checked.

1. **The charter's SHAPE goes inside the envelope, and the charter itself is
   not mirrored.** The-board-charter's naming functions hard-code `.skapa.json`
   (`snapshotName` · `autosaveName` · `snapshotsFor`) and `parseBoard` refuses
   any `format` but `"skapa-board"`. Its CODE cannot serve a `.scribe.json`.
   What crossed is its LAWS, written out in `src/lib/bind.ts` and kept:
   unknown keys carried as sacred · snapshots never overwrite · the id minted
   once and never derived from the name · the version never upgraded silently.
   `encodeWorkId` / `decodeWorkId` / `snapshotStamp` / `snapshotName` are the
   charter's four functions in this studio's own suffix, and they are named as
   such in the file's own comments.
2. **The scene-break marker is `***`, and it is the only one that could be.**
   The-pandulipi honours `#`, `***` and `* * *` (`SCENE_LINE`). The-binder's
   `RULE` (`-{3,}|\*{3,}|_{3,}`) makes `***` an `<hr/>` — a break. A lone `#`
   is NOT a heading to the-binder (its `HEAD` requires a space after the
   hashes), so it would be set as ordinary text: a hash printed in the book.
   And `* * *` matches the-binder's `ITEM`, so it would be set as a bulleted
   list whose one item is `* *`. One marker is a break in both, and it is
   `***`. Proven over a two-scene fixture, both directions, in the proof.
3. **The ZIP is store-only.** Method 0 for every entry, `mimetype` first with
   no extra field, timestamps pinned to the DOS epoch. A store-only EPUB is a
   valid EPUB; what the OCF actually insists on is that `mimetype` is first and
   stored, and here that holds for every entry rather than for one. No deflate,
   so no `node:zlib`, so nothing of the-binder's node door had to cross.
4. **One door to the disk.** `src/lib/host.ts` holds every
   `@tauri-apps/plugin-*` call and `appDataDir`, and no room, store or water
   imports a plugin. Its twin is `src/lib/base.ts`, which holds the only
   `invoke` in the repo. Between them, everything this window can reach outside
   itself stands in two files, and the proof prints the list of files it
   searched to say so.
5. **An import is a NEW work.** Never a merge. The envelope's third law is that
   an import is non-destructive, and a work is one thing — there is no key by
   which two of them could be reconciled without one losing.
6. **Unknown keys are told, not stored.** The charter's law says a reader keeps
   whole what it does not understand. This base has no column to keep it in,
   and inventing one would be a schema change smuggled in through an import
   road. So every unrecognised key is NAMED on the screen and here, and the
   file — which still holds them all — is never altered.
7. **No autosave slot.** The base on this device is this studio's autosave; the
   desk has already written every keystroke into it. The room says so in one
   line rather than leaving the absence to be discovered.
8. **The room reads the clock; the water never does.** The-binder refuses a
   blank `dcterms:modified` rather than guessing one, and it is right to.
   `src/lib/bind.ts` takes every moment as an argument.

## THE CHOICES, and why

1. **`src/lib/bind.ts` has three runtime imports and they are all from
   mirrors.** `crc32` and `utf8` from the-binder (pure arithmetic over bytes;
   the water computes UTF-8 by hand precisely so a consumer need not reach for
   `TextEncoder`), and `seal` from the-envelope. The plan named the first two
   as lawful; `seal` is the third and it is named here rather than slipped in.
   Its one impurity is that it stamps `exportedAt` from the clock INSIDE the
   mirror — the water's own doing, not this file's, and a mirror is not edited
   to please a law of this repo's. No line written in `bind.ts` reads a clock.
2. **The proof teaches Node one thing: `$lib`.** S2's proof ran `board.ts` in
   node because every import in it was `import type`. `bind.ts` has value
   imports, so the proof registers a single `module.registerHooks` resolver
   mapping `$lib/x` to `src/lib/x.ts` or `src/lib/x/index.ts` — SvelteKit's own
   alias, from `.svelte-kit/tsconfig.json`. Nothing is transformed and every
   file is read from disk as it stands. No `tsx`, no install. **The alternative
   was `allowImportingTsExtensions` in `tsconfig.json`**, which would have
   loosened a shared file house-wide to serve one proof; ten lines in the proof
   is the smaller change.
3. **`manuscriptFolderOf` hands back the byte OFFSETS of every body it
   placed.** `placed: { file, partId, at, end }[]`. The-binder's own law is
   that a promise the text was not altered is worth nothing and an offset is
   checkable by anybody; this file keeps the same law on the same terms, and
   the proof checks a slice equality rather than a substring search.
4. **A scene's TITLE does not travel, and it is told every time.** On a
   manuscript page a scene is a break, not a heading. The studio's scene titles
   are the author's own shelf-marks and stay in the studio; every scene's TEXT
   is in the file, whole.
5. **`chapterFileName` takes a `width`, defaulting to two.** At two digits
   plain name order and natural order agree, so a folder read by the-binder
   (which sorts naturally) and a folder read by anything that sorts by name
   land on the same book. Past 99 chapters they stop agreeing — `100-x.md`
   sorts before `99-x.md` by name and after it naturally — so
   `manuscriptFolderOf` widens the field to the digit count of the total and
   says so out loud. Both halves are proven.
6. **The identifier is `urn:resonance-scribe:<the work's id>`.** Stable, so
   binding the same work twice makes the same book rather than two books a
   library would file apart. Left to itself the-binder derives one from the
   title and the author, which changes the moment a work is renamed.
7. **`readingToImport` speaks in ARRAY INDICES, not ids.** The plan it returns
   carries no `id` key at any depth, so an id read from a file has nowhere to
   go even by accident — the proof asserts that none of the fixture's thirteen
   ids appears anywhere in `JSON.stringify(plan)`. Parts come back chapters
   first in `ord`, then each chapter's scenes in `ord`, which is the order the
   base appends in (`next_ord` in `base.rs`), so creating in plan order gives
   the same ordinals back. Nothing is dropped: a scene whose chapter is missing
   from the file comes in as a chapter of its own and is told; an appearance
   hand pointing at a row the file does not carry is let go and told; a row
   that ends up hanging on nothing is left out, because the base's own CHECK
   refuses it.
8. **`host.ts` has one shape the plan's list of five did not name:
   `occupied(paths)`.** The plan's own rule for the folder export is "check all
   with `exists` first", and that needs a door. `occupied` takes a list of
   paths the caller ALREADY NAMED and answers which of them stand; it cannot
   discover a file, so it is not a listing. A path it cannot answer for is
   reported as standing, because the safe reading of "I could not tell" is "do
   not write here". `appDataFolder()` is the sixth, and the plan named it.
9. **`writeNew` guards twice.** `exists` first, so the refusal is a sentence a
   hand can read with no byte moved; then `createNew: true`, so the platform
   itself refuses in the gap between the asking and the writing. The-binder's
   door keeps the same law with the `wx` flag.
10. **`snapshotName`'s never-overwrite is only half the law here, and the
    weaker half.** `host.ts` has no `readDir` — deliberately — so `existing` is
    not a reading of the disk, it is whatever the caller already knows. The
    half that actually holds is `writeNew`. The room grows `existing` by each
    name that was refused and asks again, up to five times, which is how the
    two halves meet. Written into the function's own comment, not only here.
11. **Nothing in `host.ts` throws.** A declined dialog, an occupied path and a
    plugin that failed are three ordinary answers. `Chose { path, why }` and
    `Wrote { written, why }`: `path: null` with no `why` is a hand declining,
    which is an answer and never a failure. The-envelope's `deliver` keeps the
    same rule and for the same reason — an export road that crashes on a
    cancelled dialog is how "export is broken" enters a support inbox.
12. **The told lines are a plain `<ol>` and do NOT pass through the-panti.**
    The room offers no way to sort or narrow them, and re-ordering a water's
    account of itself is not a courtesy. S2's proof asserts the-panti orders
    every list in the four rooms that show one, and the bind is excluded there
    by name; it still is, and it still shows no list of the author's rows.
13. **The rights drawer's `permits` are free words.** The-sphragis keeps
    `permits` open by KP's ⚛ reserved stroke, so nothing here offers a closed
    list to pick from. `render(it).text` is shown WHOLE, gate included, and
    `render(it).gate` is handed to the-binder as `front.rights.notice` so the
    warning is printed INTO the book and not only onto the screen.
14. **One shape had to be narrowed at the seam, and it is named.**
    The-sphragis' `SphragisSplit` carries a realm's own keys through an index
    signature (`[k: string]: unknown`); the-binder's `Rights.split` is
    `{ [party: string]: number }`. Every NUMERIC share crosses, whatever it is
    called; a key that is not a number was never a share and has no line on a
    rights page. Neither mirror was edited and nothing was cast.
15. **The app version is imported from `package.json`**, not typed into the
    room. `bump-version.py` writes the triple, and a fourth place to keep in
    step is a fourth place to drift.
